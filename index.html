TEARDOWN 01

Sliding-Window Deque vs. Token Bucket in High-Burst API Gateways

Throughput: 85,000 req/s Complexity: O(log N)

Fixed-window counters allow double-limit boundary attacks (e.g., sending 100 requests at 00:59 and 100 requests at 01:00 results in 200 requests within a 2-second interval). Token buckets allow micro-bursts that overwhelm payment partner webhook endpoints.

The Architecture: We implemented an in-memory double-ended queue (deque) using Redis Sorted Sets with millisecond epoch timestamps:

  • Atomic eviction: ZREMRANGEBYSCORE key 0 (now - window)
  • Atomic insertion & count: ZADD key now uuid followed by ZCARD key
  • Network overhead minimized using pooled Redis pipelining (< 2.1ms p99 latency).
// Redis Atomic Multi-Exec Flow
Incoming Request
    │
    ▼
[API Gateway Middleware]
    │
    ├── Extract Auth Header & Client Hash
    │
    ▼
[Redis Multi Pipeline]
    ├── ZREMRANGEBYSCORE (now - 10000ms)
    ├── ZADD (now, unique_uuid)
    ├── ZCARD (active_count)
    └── EXPIRE (key, 10s)

    ▼
Check ZCARD > Threshold?
    ├── YES ──> HTTP 429 (Retry-After Header)
    └── NO  ──> Forward to .NET 8 Upstream Pod
TEARDOWN 02

Zero-Drift Financial Ledgers: Enforcing Debit/Credit Invariants

Integrity: ACID Strict Concurrency: Optimistic (OCC)

Direct column mutation (UPDATE accounts SET balance = balance - 100) is unacceptable in scalable financial systems due to race condition double-spending and loss of audit traceability.

The Architecture:

  • Append-Only Postings: Balances are derived from immutable journal entries.
  • Mathematical Invariant: Every transaction validates Σ Debits - Σ Credits = 0 at the database trigger layer.
  • RowVersion Token: Optimistic Concurrency Control prevents simultaneous ledger update conflicts without locking the whole table.
// Atomic Transaction Verification
BEGIN TRANSACTION ISOLATION LEVEL READ COMMITTED;

INSERT INTO ledger_journal (tx_id, ts, type)
VALUES ('tx_981', NOW(), 'Escrow_Release');

-- Invariant Enforcement: Sum must equal 0
INSERT INTO postings (account, debit, credit)
VALUES 
  ('acc_escrow',  350.00,   0.00),
  ('acc_user_4',    0.00, 350.00);

-- Trigger Checks: IF sum(debit) != sum(credit) ROLLBACK;
COMMIT;
